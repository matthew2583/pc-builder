# Описание проекта "Конфигуратор ПК"

## 1. Назначение проекта

Веб-приложение для помощи пользователям в подборе комплектующих для персонального компьютера: выбор компонентов, автоматическая проверка совместимости, подсчёт стоимости и энергопотребления, сохранение/загрузка сборок.

## 2. Функциональность

- **Выбор компонентов:** Пользователь выбирает комплектующие, загруженные из базы данных.
- **Отображение информации:** При выборе компонента показываются основные характеристики и цена (пользовательский контроллер `ComponentDisplay`).
- **Автоподсчёт стоимости и энергопотребления:** Рассчитывается классом `PCConfiguration` методами `CalculateTotalCost()` и `CalculateTotalPower()`.
- **Проверка совместимости:** Реализована в `PCConfiguration.CheckCompatibility()` с проверкой:
  - совместимости сокетов процессора и материнской платы;
  - совместимости TDP кулера и тепловыделения процессора;
  - поддержки кулером типов сокетов процессора;
  - физической совместимости кулера с корпусом (высота);
  - совместимости оперативной памяти с материнской платой (количество слотов, тип памяти, максимальный объём);
  - адекватности мощности блока питания (с проверкой на минимум и с рекомендацией 125% запаса);
  - совместимости размеров материнской платы и корпуса.
- **Сохранение/загрузка конфигураций:** Сохранение в базу данных через `DatabaseHelper.SaveConfiguration()` и загрузка через `LoadConfiguration()`. Сохранённые конфигурации доступны в таблице Configurations БД и могут быть загружены или удалены пользователем.

## 3. Интерфейс

- **Главные страницы:**
  - `Default.aspx` — каталог компонентов с фильтром по типам, быстрый просмотр текущей сборки с отображением компонентов и итоговой стоимости/энергопотребления.
  - `Build.aspx` — детальный просмотр текущей конфигурации с проверкой совместимости, отображением всех выбранных компонентов и возможностью сохранения конфигурации с заданием имени (с валидацией через `RequiredFieldValidator`).
  - `Configurations.aspx` — список сохранённых конфигураций с возможностью загрузки (Load) и удаления (Delete) через команды Repeater контроля.
- **Используемые элементы управления:** стандартные ASP.NET WebForms-контролы (`Repeater`, `DropDownList`, `LinkButton`, `Button`), валидаторы (`RequiredFieldValidator`, `CompareValidator`), пользовательский контроль `CustomControls/ComponentDisplay.ascx` для визуализации компонентов.

## 4. Реализованные требования и соответствие коду

- **Язык/платформа:** C#, ASP.NET WebForms.
- **Использование AJAX (частичная отправка страниц):** Реализована через `ScriptManager` и `UpdatePanel` в `MasterPage.master` для обновления частей страницы без полной перезагрузки.
- **Использование мастер-страниц:** `MasterPage.master` служит главным шаблоном для всех содержимых страниц (`Default.aspx`, `Build.aspx`, `Configurations.aspx`).
- **Использование заказных контролов:** Пользовательский контроль `CustomControls/ComponentDisplay.ascx` используется для отображения информации о компонентах.
- **Использование контролов валидации:** `RequiredFieldValidator`, `CompareValidator` в `Build.aspx` с проверкой `Page.IsValid` перед сохранением конфигурации.
- **Использование WCF-служб:** Интерфейс `IComponentService` и реализация `ComponentService.svc` для внешнего доступа к компонентам через методы `GetComponentsByType()` и `GetAllComponents()`.
- **Использование средств управления состоянием приложения и/или сеанса:** `Session["CurrentConfiguration"]` хранит текущую конфигурацию пользователя, `Application["AllComponents"]` кэширует все компоненты при инициализации приложения.
- **Работа с БД:** LINQ-to-SQL через `PcBuilderWebApp/App_Code/DataClasses.cs` (класс `PCBuilderDataContext`) и `PcBuilderWebApp/App_Code/DatabaseHelper.cs` (методы `GetComponentsByType()`, `GetAllComponents()`, `SaveConfiguration()`, `LoadConfiguration()`, `DeleteConfiguration()`, `ConvertToComponent()`).
- **LINQ в проекте:** используется LINQ-to-SQL для запросов к базе данных (например, получение компонентов по типу, фильтрация по ID); применяются методы расширения как `Where()` для фильтрации, `Select()` для преобразования данных, `Distinct()` для получения уникальных значений (например, производители), `FirstOrDefault()` для получения первого элемента, `Sum()` для расчёта стоимости и энергопотребления в `PCConfiguration.CalculateTotalCost()` и `CalculateTotalPower()`.



### 5 Необходимые файлы
- `App_Data/PCBuilder.mdf` — база данных содержит таблицы компонентов, а также примеры совместимой и несовместимой сборок.
